Widget integration contract
===========================

- New iOS 26 WidgetKit app-extension target; embed in TheoNotesIOS. Preserve every existing target identity. Give this new target its own `.widgets` bundle suffix. Info.plist and AppGroup entitlements are in this directory; inherit the app's identity/version build settings.
- Extension sources: every Swift file at this directory's top level. Exclude Tests and this document. Set `THEONOTES_WIDGET_EXTENSION` in extension Swift compilation conditions. Do not set it in the app.
- Compile `WidgetSnapshot.swift`, `WidgetRoutes.swift`, `WidgetConfiguration.swift`, and `CaptureControls.swift` in the app as well. The OpenIntent MUST have membership in both targets, per Apple's Creating controls documentation. Existing AppIntent identities are untouched.
- Add Tests/*.swift to the existing iOS host test target (`@testable import BaerchenIOS`, the retained module identity).
- In app initialization register `WidgetCaptureRuntime.handler`, mapping WidgetCaptureAction's six cases to MobileCaptureRouter.Action. Enqueue with its supplied fresh UUID; drain using existing unlock/readiness rules. The handler must throw if unavailable; extension fallback throws, never reports a successful capture. The host owns deduplication/queue behavior. This is an explicit integration requirement, not automatically provided by foreground mode. iOS 27 additionally restricts allowedExecutionTargets to main; iOS 26 uses OpenIntent plus dual membership.
- Widget links use the configured THEONOTES_URL_SCHEME, with `://widget?action=...` or `://widget?note=...&library=...`. A bare `://widget` opens the app without creating/searching/changing anything (Next Up empty/locked/missing fallback). No persisted delivery ID is embedded: the app generates a new request for each URL delivery. Validate library hash and current note readability after unlocking before opening any note.
- The publisher writes WidgetSnapshot at Card/mobile-widgets.json in the AppGroup, not in the note database. `write(to:)` validates and atomically replaces a protected file. Redact synchronously on AppLock/settings/library/privacy changes BEFORE reloadTimelines. Fail publication by scrubbing, never keeping prior plaintext. Do not publish fixture/test-library content to the real shared container.
- Bound titles/first lines by UTF8 bytes (256/512). NextUp is mapped from Core CardPublication selection; do not duplicate ranking logic. NextUp starts at generatedAt (±1s), at most10 ordered entries through24h. notes/pinned<=200, inbox<=20, tags<=100 with<=20 notes each; envelope<=2MiB. libraryID is the active root hash, never a path. AppLock enabled even while authenticated means one locked NextUp entry and no other note data.
- Publication failures, missing group, corruption, stale>24h, timestamps>5min future, symlinks and unknown schema return no cached data. Timelines explicitly include an empty entry at expiry. WidgetCenter reload requests do not prove that the OS already removed rendered content.

Pinned configuration limits
---------------------------
Pinned suggestions expose at most200 cards from snapshot.pinned; tags expose at most100 lists plus Inbox. Separate configuredPins (<=200 cards) and configuredTags (<=100 lists,<=20 cards each) carry host-targeted existing configurations outside those discovery windows. Direct identity resolution uses these additional records first, while suggestions do not expand. All configured records must still be pinned/readable/live or relevant eligible tags when the app publishes; redacted envelopes require BOTH configured arrays empty. Schema version1 decoding treats missing configured arrays as empty for compatibility. The whole envelope remains limited to2MiB: the app must surface publication failure and scrub rather than truncate selected IDs silently. There is no guarantee for more than200 distinct configured pin IDs or100 configured tag IDs; exceeding a bound is an explicit failure, not arbitrary eviction.

WidgetConfiguration.swift contains the AppEntity/query/configuration-intent types and snapshot-only group reader. Compile this small file in BOTH app and widget targets so the host can read WidgetInfo.widgetConfigurationIntent(of: PinnedNoteConfiguration.self/NoteListConfiguration.self). WidgetRuntime.swift now contains only extension timeline providers/views and need not be compiled in the app. The host retrieves current widget configurations via WidgetCenter.currentConfigurations, filters library-qualified IDs to the active library, and passes distinct configuredNoteIDs/configuredTagIDs to publication. The extension never opens a database or wakes the app to resolve an unpublished identity. First-time discovery of pins/tags outside the suggestion windows still needs a bounded app-side selection path; this change preserves existing configurations rather than claiming unbounded discovery.
